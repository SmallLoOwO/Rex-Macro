# 採集掃描加入 strafe 挪位 — 設計

日期：2026-06-30
狀態：設計定案，待實作計畫

## 背景與問題

稀有礦採集的全方位掃描（`main._sweep_for_tracker`）目前是**原地**只用 `.` 把鏡頭轉 8 個方位（每 45°），角色身體不動。

兩個實機痛點：

1. **身體擋住中央視野**：第三人稱鏡頭在角色後背，角色身體永遠卡在畫面中下方。若追蹤框就疊在角色腳下/身後，8 個方位每一幀都被身體擋住 → 偵測不到、永遠採不到。
2. **鏡頭卡牆**：角色站在牆邊等刁鑽位置時，第三人稱鏡頭被牆推近（貼臉），看不到周圍。

## 目標

讓掃描期間**短按 D 把角色挪離牆邊、把身體挪到一側**，清出中央視野，使原本被身體/牆擋住的追蹤框露出來被偵測到並採集。

非目標（YAGNI）：
- 不做精準的橫向位移追蹤與走回（見「採後處理」）。
- 不做「鏡頭被擋」的動態偵測觸發（時機改用固定方位，見下）。
- 不新增偵測門檻；沿用既有 `tracker_shape_early_exit`。

## 機制

- **短按 D 幾秒**（不是全程長按）把角色往右挪一段，讓角色靠到畫面右側、離開牆邊。因為鏡頭始終面對角色後背，挪位後**中央/左側視野清空**，身體只佔右緣。
- strafe 是**週期性的挪位動作**，不是持續按住，**也不在 D3 開火時按住**。挪位只負責把視角弄乾淨；找到可信任追蹤框時，就照原本流程開火。

## Sweep 演算法修改（`_sweep_for_tracker`）

維持原本 8 方位（`.` ×7）、雙幀穩定 + 形狀 edge 偵測、`net_rotations` 追蹤鏡頭角度的架構，只加 strafe：

1. **strafe 時機 = 四個基本方位**：在 dir 0/2/4/6（前/右/後/左，每 90°）轉動前先**短按 D 幾秒**挪位；斜角方位 dir 1/3/5/7（45°/135°/…）純轉視角不挪。
   - dir 0（前）首幀沿用「前不用特別挪」：角色本來就向前、身體在後方、前方已清空，故首幀可不挪（實作時做成可設定，預設略過 dir 0 的挪位）。
2. **偵測不變**：雙幀穩定（誤差 < 8px）+ 形狀 edge 分數。
3. **就地開火**：某方位偵測到**可信任**追蹤框（`edge ≥ tracker_shape_early_exit`）→ 停止掃描、**就地**跑 D3 開火序列（按 2 → 3 → 在追蹤框螢幕座標點擊）。**不轉回、不走回**。開火時**不按住 D**（挪位已先把視角弄乾淨）。
4. **弱候選處理**：整圈掃完只有弱候選（無一過 `tracker_shape_early_exit`）→ **重掃（重新 D2）或 `_harvest_giveup` 交人工**。**絕不**走回弱框開火。
5. **不追蹤 strafe 位移、不走回**：因為 (3)(4) 都不需要回原位，省去橫向位移的計數與反向走回。只保留 `net_rotations` 給鏡頭 `restore_view`。

## 開火 D3

維持現狀：先按 2（切離 D3）→ 等 0.15s → 按 3 → 等 0.3s → hold click 0.4s → 等 0.5s 在追蹤框座標。**不按住 D**。

## 採後處理

- 採集成功 → `restore_view(net_rotations)` 只把**鏡頭角度**轉回，`init_mining_sequence()` 從角色**當前（已飄移）位置**繼續挖礦。
- **接受橫向飄移**：挖礦只是「按住 W + 左鍵」往前挖，從新位置往前挖沒問題，毋須回到原座標。

## 風險 / 實機驗證點（非阻擋項）

1. **短按 D 後身體是否仍離中央**：使用者實機觀察為「角色靠右、鏡頭面背」。若鏡頭會把角色拉回正中，需在 D 仍生效的時間窗內擷幀才抓得到離心狀態 → 挪位後的擷幀時機要實機調。
2. **右緣自我遮擋**：身體靠右後，畫面最右緣由身體佔據，落在最右緣的追蹤框該方位會漏；但 360° 旋轉會由相鄰方位補拍到。
3. **`reference_bgr` 差分更弱**：strafe 讓畫面位移更大，差分（假設鏡頭靜止）更難排除「掃描前就有的」→ 更依賴與位置無關的**形狀確認**。形狀確認本就是現行主閘門，可接受。
4. **挪位距離/秒數需調**：「幾秒」在遊戲內位移不小，整圈 4 次挪位會把角色帶到明顯偏右；以 config 秒數調到「夠清視野又不過度飄移」。

## Config / 設定

- 新增旋鈕（暫定）：`sweep_strafe_key="d"`、`sweep_strafe_hold_s`（短按秒數）、`sweep_strafe_dirs`（預設 {2,4,6}，即右/後/左；前 dir 0 預設不挪）。
- **不新增偵測門檻**。

## 測試策略

- sweep 本身 I/O 重，難純測；把**「該方位要不要挪位」**與**「就地開火 vs. 重掃/交人工」**的決策抽成小純函式（風格比照 `harvester.decide_harvest_result`）做 TDD 單元測試。
- I/O 串接（key_down/up 順序、挪位→轉動→擷幀的時序）以實機驗證點清單人工驗收。

## 與既有規則的相容性

- 不違反「數字鍵 toggle」「`.`/`,` 轉 45°」「init 完整序列恢復挖礦」等硬規則。
- D 為移動鍵，不與裝備數字鍵/點擊衝突（待實機確認第 4 點時順帶確認）。
