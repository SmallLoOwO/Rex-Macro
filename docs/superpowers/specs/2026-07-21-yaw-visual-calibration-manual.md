## 這份文件的用途

回礦落地後角色約一半機率朝對角，影響挖礦效率。2026-07-21 使用者裁決**先用
手動 `轉` 指令**（commit `674d602`）解決，不做自動判定。

本手冊記錄**若日後要自動化，該怎麼做**：可行的演算法、實測數字、已證實無效
的死路、整合點與風險。目的是讓下一個人不必重跑一遍實驗。

**本文不含已調好可直接上線的門檻。** 第五節的建議值來自 n=3 實驗，上線前必須
補樣本。

## 一、問題與根因

回礦每輪 attempt 都按「回到地表」換重生點，遊戲**隨機化 yaw**。八方位 sweep 的
`cur_dir=0` 基底＝該輪 reroll 後的隨機朝向，所以 `b9f7783` 的
`restore_view(ctx.cur_dir)` 扣掉使用者方位偏移後，回到的仍是隨機基底——直角／
對角各約一半（使用者實測頻率確認）。記帳救不了：沒有絕對 yaw 感測器。

### 關鍵結構事實（先讀，不然會走錯方向）

- **角色身體才是世界軸參考，鏡頭才是歪的那個。** Click to Move 模式下角色身體
  不跟著鏡頭轉，`,`/`.` 轉的是**鏡頭繞著靜止的角色**。所以判斷對象是「鏡頭相對
  角色的角度」，不是牆壁或地形。
- **四個對齊位置（正面／正後／左右兩側）對本用途等價**——都是軸對齊。演算法
  只需避開 45°，不必分辨是哪一個。
- ⚠ **不可假設起始位置是對齊的。** 2026-07-21 實驗起點實際是「右後方」（45°），
  前五次量測因此拿反標籤全部作廢。每次都要獨立確認 ground truth。
- ⚠ 「LIMIT」徽章與層名牌是**螢幕空間 UI**，八方位掃描中位置完全不動，不可
  當世界物件用來判朝向。

## 二、演算法：參考圖比對（相對排序）

存一張「正後方」實機裁圖當參考。判斷時原地轉一圈 8 格、每格截圖，取與參考圖
**最相似**的那格。

```
ref = 正後方參考裁圖（實機拍，assets/）
for i in range(8):
    shots[i] = capture.grab()
    rotate_verified(+1)          # 8 次同向＝轉滿一圈回原向
scores = [shape_iou(ref, s) for s in shots]
best, gap = argmax(scores), top1(scores) - top2(scores)
if gap < GAP_MIN:  → 不轉，警告「參考圖已失效，請重新校準」
else:              → 轉到 best
```

### 為什麼是排序而不是分類器

分類器要「這一幀是不是對齊」的**絕對門檻**，而絕對分數會隨造型、光照、層別
漂移（實測 0.936 → 0.899 → 0.571 連續下滑，找不到切點）。排序只要求同一輪
8 張之間可比，天然免疫這些漂移。這也是 2026-07-21 六種分類特徵全部失敗、
而排序法可行的根本原因。

8 次同向旋轉＝轉滿一圈回原向，所以取樣本身不改變狀態（實測首尾幀差 0.40，
每步相鄰幀差 9~21 確認每次都真的轉了）。

## 三、指標：形狀 IoU，不是灰階相關

兩個候選都在角色 ROI 上算，背景牆先遮除：

- **灰階相關**：ROI 灰階做 zero-mean 正規化互相關。
- **形狀 IoU**：角色遮罩（非綠牆像素）與參考遮罩的交集／聯集。**只看剪影輪廓，
  不看顏色與貼圖。**

實測參數（1920×1080）：

```python
R = (slice(430, 830), slice(820, 1230))     # 角色置中裁切
hsv = cv2.cvtColor(img[R], cv2.COLOR_BGR2HSV)
wall = (hsv[:,:,0] > 45) & (hsv[:,:,0] < 90)  # 綠牆
mask = cv2.morphologyEx((~wall).astype(np.uint8),
                        cv2.MORPH_OPEN, np.ones((5,5), np.uint8))
```

⚠ ROI 與綠牆 hue 範圍是在 Shamrock 層量的。**換世界／換層必須重驗**——牆色不同
會讓遮罩整個失效。這是本方案最大的未驗證面。

## 四、實測數據（造型變動三輪）

全部拿**最初造型的正後方參考圖**比對，ground truth 每輪肉眼確認。

| 輪次 | 造型狀態 | 灰階 第一/第二（間距） | IoU 第一/第二（間距） | argmax |
|---|---|---|---|---|
| A | 原造型（參考圖本人） | 0.8400 / 0.3118（**0.528**） | 0.9362 / 0.7297（**0.207**） | 皆 ✓ |
| B | 換身體與衣服，配件留著 | 0.6126 / 0.4042（0.208） | 0.8990 / 0.7074（0.192） | 皆 ✓ |
| C | 造型＋配件全換 | 0.2297 / 0.2277（**0.002**） | 0.5710 / 0.4881（**0.083**） | 灰階 ✓（擲銅板）／IoU 選到正面 |

**灰階相關不可用**：C 輪第一二名只差 0.002，argmax 正確純屬運氣。

**形狀 IoU 可用但需失效偵測**：B 輪幾乎沒衰退（0.207 → 0.192），C 輪掉到 0.083。
C 輪 IoU 完整排序 5,1,3,4,2,6,0,7——四個對齊位置有三個仍在前段，方法沒完全
失靈，但已不足以信賴。

## 五、失效偵測：第一二名間距

**判準用間距，不用絕對分數。** 理由見上表：絕對分數連續下滑無切點，間距則在
A/B（≈0.19-0.21）與 C（0.083）之間有明顯斷點。

建議起點 `GAP_MIN = 0.15`：A/B 通過、C 擋下。

> ⚠ **這是 n=3 的建議值，不是可上線的門檻。** 本專案慣例（H040／H054）要求
> 兩側夾＋足夠樣本。上線前至少要補：多世界／多層、多次造型變動、不同光照，
> 各取數輪，確認 0.15 兩側都有餘裕。**在那之前不得寫死。**

失效時的行為：**不轉**，發警告要求重新校準。絕不「硬選最高分然後轉過去」——
把直角誤判成對角會多轉 45° 反而製造對角，比不轉更糟。

## 六、已證實無效的路線（不要重做）

2026-07-21 逐一量測，全部無法兩側夾：

| 特徵 | 結果 |
|---|---|
| 左右鏡像對稱度（整幀） | 10/14 輪一致（隨機期望 7/14） |
| 線段數（階梯 vs 連續平面） | 9/14 輪 |
| L-R 亮度差 | FACE 1.25~41.50 vs DIAG 1.33~20.84，完全重疊 |
| 牆地交界左右斜率差 | FACE 0.37~0.94 vs DIAG 0.23~0.78，完全重疊 |
| 軀幹著色階 | 完全重疊 |
| 剪影左右對稱（IoU） | 預測「正後/正面最高」落空 |

失敗原因已查明：

- **角色裝飾高度不對稱**（緞帶、武器、工具），不論鏡頭角度都一樣歪，吃掉所有
  剪影／著色統計。
- **礦石方塊又亮又不對稱**，主導亮度統計。實例：某幀是對齊位置卻拿到最大 L-R
  差 41.50，來源是右上角一塊黃礦。
- 地形候選（地板格線、礦脈走向）**在落地當下不存在**——礦層是實心岩，還沒開挖。
- HUD **沒有 compass／小地圖**。

## 七、整合設計

### 觸發時機

`_rr_success` 內、`harvester.restore_view` **之後**、`_rr_finalize` 之前。理由：
語料與判斷都要反映 bot 實際開挖的那個面向，在回正前做會多帶使用者的方位偏移。

`cfg.reentry_yaw_sample_sweep`（commit `e2182f6`，目前預設關）已經實作了「原地
八方位取樣＋轉滿一圈回原向＋旋轉被吃記數警告」的迴圈，**可直接改造成判斷迴圈**，
不必重寫。

### 執行緒邊界

比照既有鐵律：Discord 輪詢執行緒只寫旗標，**所有 `input_control` 呼叫一律在
主迴圈**。重新校準指令走 `_pending_*` 旗標模式（同 `_pending_ability`／
`_pending_rotate`）。

### 重新校準指令

換造型後參考圖即失效，必須有重拍管道。比照既有 `capture_template` /
`calibrate_surface` / `calibrate_pitch` / `add_chill_ref` 的慣例：

1. 使用者把鏡頭轉到正後方（可用現有 `轉` 指令逐格調）
2. 下指令 → 主迴圈截圖、裁 ROI、存檔到 `assets/`
3. 回覆確認圖供目視驗收

**新指令必須同步更新玩家可見訊息**（`help`＋回礦卡指令清單），否則玩家不知道
能用——07-20 `退` 指令即犯此漏。

### fail-safe

- 間距不足 → 不轉＋警告（見第五節）
- 旋轉被吃 → 用 `_rotate_verified`，記數警告；被吃會讓方位標籤錯位，該輪判斷
  不可信
- 中途遇 reset／暫停 → 停手，並警告殘留旋轉造成的面向偏移
- 缺參考圖 → preflight 警告，功能視同關閉（同 `_panel_templates` 慣例）

## 八、測試計畫

**純函式**（不碰 I/O，可完整覆蓋）：

- `shape_iou(mask_a, mask_b)` — 已知遮罩對，驗算術
- `pick_best_direction(scores, gap_min)` → `(best_idx, trustworthy)`
  - 清楚勝出 → 回該格、可信
  - 擠成一團（間距 < gap_min）→ 不可信
  - 並列最高 → 不可信（不可任選一個）
  - 空／長度非 8 → 不可信

**整合**（mock 視覺回傳值）：

- 可信 → 轉到 best，轉動次數正確
- 不可信 → 一次都不轉，發警告
- 旋轉被吃 → 記數警告，不中止
- 中途 reset → 停手並警告

**實機**：多世界／多層採樣，補第五節門檻的兩側夾數據。
