# Roblox 挖礦遊戲自動化 — 設計文件

- 日期：2026-06-23
- 狀態：設計確認中
- 目標平台：Windows 10、Roblox（1920×1080 視窗化為主，支援自動偵測視窗）

---

## 1. 背景與目標

**現況**：目前有 6 個 Pulover's Macro Creator 巨集（`.mcr`，底層 AutoHotkey），負責 Roblox 挖礦遊戲的自動掛機：
- 挖礦循環（按住 W + 左鍵）
- 槽位偵測（像素 → D1 切回）
- 視窗失焦復原（偵測頂部像素 → 重新聚焦 Roblox）
- 事件彈窗處理：boost（D5）/ skip（D4）/ scan（D2,Z）/ cave（F 進出洞穴）

**目標**：全部用 Python 重寫成單一程式，並新增：
1. **稀有礦物自動採集**：偵測到頂部「A chill goes down your spine...」字樣 → 自動 D2 掃描 → 對準 → D3 遠距挖礦 → 驗證
2. **失敗才人工介入**：自動採集失敗（瞄不到/挖不到）時暫停並提醒使用者接手
3. **（階段二）Discord 事件記錄**：把「找到稀有礦」「需要人工介入」「腳本卡住」等事件送到 Discord

**chill 的本質**：當 Exotic 階級礦物被挖出時，遊戲會播放一個悶悶的「boom」聲（俗稱 chill）。Exotic 是最低的「有挖出音效」階級。開啟 **Disguised Chills** 設定後，所有選定的更高階級也會播放這個相同的 chill 聲（且頂部文字統一為「A chill goes down your spine...」）。

**最初需求對應**：使用者原本想要「聽到特定聲音停止」。本設計採 **音訊偵測為主 + OCR 文字二次確認**：用使用者提供的參考音檔（chill boom 聲）做音訊指紋即時觸發，再用 OCR 確認頂部文字，兼顧即時與可靠。參考音檔將複製進專案作為比對樣本（asset）。

3. `pip install -r requirements.txt`

## 4. 系統架構（狀態機）

主迴圈每約 50ms 擷取一幀，依當前狀態決定動作：

```
                 ┌──────────────────────────────────────┐
                 │  擷取螢幕 (每 ~50ms 一幀)             │
                 └──────────────────┬───────────────────┘
                                    ▼
   ┌────────────┐  偵測到 chill   ┌──────────────┐  瞄準失敗/超時   ┌──────────────┐
   │ MINING     │ ──────────────► │ HARVESTING   │ ───────────────► │ NEEDS_HUMAN  │
   │ 挖礦+事件  │                 │ 稀有採集     │                  │ 暫停+提醒    │
   └─────▲──────┘  輪廓消失=成功  └──────┬───────┘                  └──────┬───────┘
         │         ◄──────────────────────┘                                 │
         └─────────────────────── 使用者熱鍵手動恢復 ◄──────────────────────┘
```

- **MINING**：挖礦循環 + 事件處理 + 視窗失焦復原 + 卡住偵測
- **HARVESTING**：接管，做掃描 → 對準 → D3 → 驗證
- **NEEDS_HUMAN**：暫停所有自動輸入，本機提醒，等使用者熱鍵恢復

每次狀態轉換與關鍵事件都送入統一 EventLog（第 9 段）。

## 5. 模組分解

| 模組 | 職責 | 主要依賴 |
|------|------|---------|
| `config.py` | 集中所有座標、顏色、模板路徑、容差、超時、嘗試上限、熱鍵、Tesseract 路徑 | — |
| `capture.py` | 抓取 Roblox 視窗畫面（全視窗或指定區域） | `mss` |
| `audio.py` | 擷取系統喇叭輸出（loopback），用 chill 參考音檔做指紋比對，偵測 chill boom 聲 | `pyaudiowpatch`, `scipy`, `numpy` |
| `vision.py` | 模板比對、礦物標記定位、判斷輪廓是否存在 | `opencv`, `numpy` |
| `ocr.py` | 讀畫面文字：chill 提示、聊天框「has found X」 | `pytesseract` |
| `input_control.py` | 送按鍵/滑鼠：W、D1–D5、`.`/`,`、Shift、左鍵、移動滑鼠瞄準 | `pydirectinput` |
| `miner.py` | MINING 狀態邏輯（移植 `.mcr`） | 上述 |
| `harvester.py` | HARVESTING 狀態邏輯（採集演算法） | 上述 |
| `events.py` | EventLog 統一介面 + Discord 掛接點 | （階段二 `requests`） |
| `calibrate.py` | 一次性校準工具：確認視窗與關鍵 UI 區域 | `capture`, `vision` |
| `main.py` | 狀態機主迴圈 + 全域熱鍵（緊急停止/暫停/恢復） | 全部 |

**原則**：所有「畫面座標、顏色值、超時秒數、嘗試上限」集中在 `config.py`，UI 位置變動時只需改一個檔。每個模組單一職責、可獨立測試。

## 6. 各狀態詳細邏輯

### 6.1 MINING（移植自現有 `.mcr`）
- 初始化序列：放開 W/左鍵 → `.`、`,` 調整視角 → 連按兩次 Shift → 槽位像素偵測（顏色 `2302755` → 按 D1）→ 按住 W + 左鍵
- **視窗失焦復原**：偵測頂部像素（顏色 `2829099`，區域約 `2,897→18,988`）→ 重新聚焦 Roblox 視窗 → 重跑初始化序列
- **道具/事件處理**（用 OpenCV 模板比對取代 `.mcr` 的 `IF IMAGE`，可調容差）：
  - **D5（加成工具）**：偵測右下角的加成效果指示，效果結束時重新按 D5 上 buff → 點擊 → D1 → 續挖
  - **D4（控制活動工具）**：頂部中央出現「活動事件」時按 D4 控制活動（取得加成）→ 點擊/右鍵 → D1 → 續挖
  - scan 變體 → D2 / Z / D5 組合
  - cave 變體 → F 進入 → 等待 → 自動退出（`.`、`,`、X）

- **D4 活動事件 vs chill 的區域衝突處理**（重要）：
  - D4 的活動事件與 chill 文字**共用頂部中央區域**，須避免互相誤判。
  - **主要區分依據 = 音訊**：D4 活動事件**不會**播放 chill 的 boom 聲（已確認），只有真正的 chill 有。因此音訊偵測器只對真 chill 反應，天然分離兩者。
  - **次要保險**：OCR 比對特定字串「A chill goes down your spine」；且**狀態機同一幀只處理一件事**（chill 觸發 → HARVESTING 優先；非 chill 的頂部事件 → 留在 MINING 由 D4 處理），不會同時觸發。
- **STUCK 偵測**：MINING 狀態下若連續 N 秒（可設定）畫面/進度無明顯變化 → 觸發 `STUCK` 事件並提醒

### 6.2 HARVESTING（核心新功能）
流程：
1. 進入時放開 W、放開左鍵（停止挖礦）
2. 按 **D2** 掃描 → 等待礦物標記出現
3. `vision` 找出礦物標記在螢幕的座標 `(mx, my)`
4. **水平對準**（不調整遠近，D3 為遠距工具）：
   - 用 `,` / `.`（每次轉 45° 視角）把礦物轉到面前
   - 再用滑鼠微調，把準心（畫面中心）對到礦物中心點
5. 按 **D3** 遠距挖礦
6. **驗證（限時）**：
   - 成功：輪廓消失（vision）+ 聊天框出現「has found X」（OCR）→ **雙重確認** → 記錄礦物名 → 回 MINING
   - 失敗：超過設定秒數或嘗試 M 次仍未成功 → 進 NEEDS_HUMAN
7. **垂直極端判定**：若數輪水平轉視角後仍無法把標記帶到畫面中央水平線附近（代表礦物在頭頂/腳下）→ 直接放棄自動 → NEEDS_HUMAN

### 6.3 NEEDS_HUMAN（安全網）
- 暫停所有自動輸入
- 本機提醒：播放音效 + 桌面通知
- 記錄事件（含原因：瞄準失敗 / 垂直極端 / 驗證超時）
- 等待使用者按「恢復」熱鍵後回到 MINING

## 7. 偵測技術

- **chill 觸發偵測（音訊為主 + OCR 確認）**：
  - **主觸發（音訊）**：`audio.py` 持續擷取系統喇叭輸出（WASAPI loopback），用使用者提供的 chill 參考音檔做指紋/頻譜模板，以正規化交叉相關比對。該 boom 為低頻、特徵明顯的聲音，可行性高；靈敏度門檻需實測調參，避免被挖礦音效誤觸。
  - **二次確認（OCR）**：音訊觸發後，OCR 讀頂部中央固定區域比對「A chill goes down your spine」。使用者已同意開啟 **Disguised Chills** 設定固定此片語；另保留一組已知片語（如「Your heart skips a beat」）作為備援比對。
  - **判定**：音訊觸發 + OCR 在限時內確認 → 進入 HARVESTING。僅音訊觸發但 OCR 未確認 → 記錄為可疑事件、暫不接管（避免誤判），可設定為提醒。
- **成功確認**：OCR 讀左上聊天框最新一行，比對「has found」/「found a spectral」等關鍵字，並由 vision 確認輪廓消失，雙重確認避免誤判。
- **事件彈窗**：OpenCV 模板比對，容差可調（比 `.mcr` 的 `IF IMAGE` 更穩）。模板可沿用現有巨集內嵌的 bitmap，或重新截圖製作。
- **礦物標記定位**：以模板比對 + 顏色 blob 偵測找出掃描後的小標記座標。**此處準確率需用真實遊戲截圖反覆調參**，第一版求「能動」，再靠實測微調；NEEDS_HUMAN 為其安全網。

## 9. 事件系統與 Discord 掛接（`events.py`）

統一介面：
```python
log_event("RARE_FOUND", mineral="Spectral 4FA208", tier="Spectral")
log_event("HARVEST_SUCCESS", mineral="...")
log_event("NEEDS_HUMAN", reason="瞄準失敗 3 次")
log_event("STUCK", reason="挖礦循環 60 秒無進度")
log_event("STATE_CHANGE", from_="MINING", to="HARVESTING")
```

- **階段一**：輸出到本機 log 檔 + 桌面通知
- **階段二**：同一批事件轉發到 Discord Webhook（單向訊息，一個 URL 即可）。若未來要雙向控制再升級為完整 bot。

## 10. 熱鍵控制（`main.py`）

- **緊急停止**：立即停止所有自動輸入並結束程式
- **暫停 / 恢復**：手動暫停或恢復自動化
- **手動確認恢復**：NEEDS_HUMAN 狀態下，使用者處理完後按此鍵回 MINING

## 11. 風險與安全網

- **瞄準準確率**：依賴電腦視覺，需用真實截圖調參。安全網 = NEEDS_HUMAN 在自動失敗時接手。
- **誤判**：成功偵測採雙重確認（輪廓消失 + 聊天框文字）降低誤判。
- **遊戲服務條款**：自動化可能違反 Roblox / 遊戲 ToS，存在帳號風險。本工具供個人單機掛機使用，使用者自負風險。
- **解析度/UI 變動**：以視窗自動偵測 + 校準工具降低脆弱度。
