# 礦坑重置自動重新進礦（Auto Re-entry）設計

日期：2026-07-08
狀態：設計定案，待實作計畫

## 目標與可行性結論

礦坑重置後，bot 目前進 `RESET_WAIT` 停下等人工重新定位。本設計把「按回到地表 → 找傳送面板 → 點目標層級按鈕 → 回礦開挖」自動化，是腳本的最後一塊拼圖。

**可行性：可行，風險有界。** 最壞結局＝重試次數用盡交 `NEEDS_HUMAN`＝今天的現狀；此功能只把「每次重置必等人工」變成「大多數自動、少數等人工」，不存在比現狀更糟的失敗模式。唯一要認真防的是**點錯層級按鈕、傳錯層後渾然不覺**——由「高信心才點＋按鈕文字 OCR 驗證＋進礦通知附截圖」三層把關。

## 已確認的事實（2026-07-07~08 與使用者問答＋實機截圖）

| 環節 | 事實 | 對設計的意義 |
|---|---|---|
| 人工流程 | 重置後人還在礦裡（安全）→ 點右下「回到地表」UI 按鈕 → 傳到地表隨機重生點 → 找傳送面板點目標層 → 回礦、落點即挖 | 流程 A；落點即挖＝進礦後直接接 `init_mining_sequence` |
| 回到地表按鈕 | 螢幕覆蓋層 UI、位置固定 | 盲點固定座標，零視覺 |
| 防範機制 | 隨機旋轉只亂 yaw；俯仰是挖礦自己抬頭弄歪的殘留 | 俯仰用「拖到底夾限→回拉固定量」歸位；yaw 用 `,`/`.` 八方位掃描 |
| 重生點 | 多個、位置有連續性偏移，部分點不到面板 | **不可用「每重生點一張校準表」**（偏移連續、視角每次不同）；偵測必須錨定面板本體 |
| 壞點復原 | 再按一次「回到地表」reroll＋轉視野 | 天然重試迴圈；reroll 也是萬用脫困鍵 |
| 面板互動 | 滑鼠點擊、**無距離限制**，但要畫面上點得到 | 問題從「導航」降級為「找角度＋看得清＋點得準」 |
| 面板外觀 | 「Teleportation Board」：紫色外框＋深色板面＋按鈕格；遠距模糊、可能只露一角；本身是遊戲設施、**各世界一致** | 偵測錨點＝面板本體（world-agnostic）；旗幟/橋等地標是單一世界景物，**不當參考** |
| 面板按鈕 | 頂部全寬「Back to pre-reset location」（回重置前舊座標——挖礦越挖越深，重置後舊座標無意義，**不用**）；下方各層級按鈕（Basalt/Diorite/Obsidian/Mantle/Core…，標價 $1.00–$5.50），傳到該層**頂部** | 目標＝使用者指定的層級按鈕（校準時標注哪一顆） |
| 誤點風險 | 亂點無害，但點到別的層級按鈕會傳錯層（傳錯仍可 reroll 回地表；傳錯層挖礦是效率問題非安全問題） | 「寧漏勿誤」：OCR 驗證按鈕文字對得上才點 |
| Click to Move | 右鍵單擊可讓角色自動走到指定處（含上樓梯/繞路）；**面板前的地面點不動，直接右鍵點面板本體可導航**；到位後角色可能擋住面板，有時再點右鍵重導航可解、有時不行 | 導航交給遊戲引擎，刪除盲走/跳躍/側移邏輯；遮擋走處理階梯（見 B 階段） |
| 地形案例 | 有些重生點與面板隔一座橋/樓梯（實機圖：橋對面高台上） | click-to-move 自動爬坡；走不到＝reroll，不是 NEEDS_HUMAN |

## 第 1 節：狀態機與觸發時機

- 新增狀態 `REENTRY`。`RESET_WAIT` 語意從「停下等人工」改為「等重置完成」：背景 banner OCR（現成 `_banner_ocr_loop`）偵測 reset 字樣**消失**＋沉澱數秒 → 轉入 `REENTRY`。
- config 加 `auto_reenter: bool`；關掉＝完全回到今天的行為（`RESET_WAIT` 等人工）。
- Q / Ctrl+Q / F12 熱鍵在 `REENTRY` 全程有效，人工隨時可接手。
- `REENTRY` 比照 `harvester`：**決策是純函式小狀態機**（`reentry.py`，可 TDD），I/O 由 `Bot._tick_reentry` 執行。

### 運行時主迴圈

```
按「回到地表」(固定UI座標盲點)
→ 等傳送完成（幀差大變化）
→ 俯仰歸位（右鍵拖到底夾限 → 回拉校準量；用 input_control.aim_move）
→ A. 八方位掃描（,鍵×8，沿用 _rotate_verified）：每方位跑面板偵測
→ B. 命中 → 右鍵單擊面板 bbox 中心（click-to-move 自動走近，到位偵測）
→ C. OCR 面板區域 → 找目標層級的文字框 → 左鍵點擊該框中心
→ 驗證傳送發生（幀差）＋ 礦內場景簽名 → init_mining_sequence → MINING
→ 任一步失敗 → 再按「回到地表」reroll，attempts+1
→ attempts ≥ max_reentry_attempts(預設 5，config 可調) → NEEDS_HUMAN（附截圖）
```

- 每輪 reroll 有獨立超時（`reentry_attempt_timeout_s`，預設 60s，比照 `sweep_timeout_s`），保證單輪不卡死。

## 第 2 節：離線校準工具 `python -m miningbot.calibrate_surface`

互動式，兼任可行性實機驗證。產出：

1. 面板偵測模板：從實機截圖裁面板外框（近/中/遠多尺度樣本），存 `assets/surface/`。
2. 俯仰校準量：R 視窗選定「距夾限 N 像素」寫入 config。
3. 礦內/地表場景簽名（亮度/特徵），供傳送後驗證。
4. 目標層級名稱字串（如 `Mantle Layer`）寫入 config——不需要標注座標，點擊位置由運行時 OCR 文字框決定。

### 校準時必須實機確認的清單（有意外回頭修設計）

- `,`/`.` 在地表是否照常 45° 一格。
- 俯仰「拖到底→回拉」歸位是否穩定可重現。
- 「回到地表」按鈕有無冷卻；重置完成的確切訊號（banner 字樣消失後多久可按）。
- **右鍵「短點」＝click-to-move vs 右鍵「按住拖曳」＝轉鏡頭**，遊戲是否正確區分（`aim_move`/俯仰歸位靠後者）。
- Click to Move 是否需要在 Roblox 設定開啟；開啟後**挖礦主迴圈「按住 W＋按住左鍵」是否完全不受影響**（絕不能退讓；若衝突改成「只在 REENTRY 期間臨時切換移動模式」）。
- 點層級按鈕會不會跳確認彈窗；層級按鈕的價格扣什麼、餘額不足的表現。
- 地表有無日夜/天氣造成的背景變化（影響模板比對）。

## 第 2b 節：R 鍵取樣視窗

- 熱鍵 **R**（config 可改），走現有 `Bot._check_hotkeys` 全域輪詢，任何狀態（含暫停/NEEDS_HUMAN/RESET_WAIT）都有效。
- 按 R 彈出小型置頂視窗（比照 `status_hud` Tkinter）：
  - **俯仰歸位**鈕：拖到底夾限→回拉預設量；
  - **上/下微調**鈕：每按一次 `aim_move` 拖固定像素，即時顯示「距夾限偏移量」；
  - **截圖**鈕：存 `logs/snapshots/manual/NNN.png`＋同號 sidecar `NNN.json`（俯仰偏移量、時間戳）；編號 3 位數流水號，啟動時掃描資料夾接續最大號；寫檔走非同步 snapshot worker；
  - **測試右鍵走路**鈕：記錄「點擊座標＋到位耗時」進 sidecar，累積 click-to-move 實測數據。
- HUD 閃「📸 手動截圖 #NNN」＋寫 `miningbot.log`，使用者當場知道編號、日後直接指名「用 007 當樣本」。
- 用途不限 re-entry：裁追蹤框模板、補 chat OCR fixture 都可用同一顆鍵留檔。

## 第 3 節：偵測、導航與點擊（防傳錯層的核心）

### A. 找方向
- 俯仰歸位到校準仰角 → 八方位掃描，每方位跑面板偵測：色不變、多尺度邊緣比對（沿用 boost/marker pipeline），模板＝實機裁的面板外框。取最佳 `(yaw, bbox, score)`，**高信心才進下一步**，低於門檻寧可 reroll。

### B. Click to Move 導航＋遮擋階梯
1. 右鍵單擊面板 bbox 中心 → 角色自動走近（地面點不可點，實測確認）。
2. 到位偵測：輪詢 bbox——持續變大＝在路上；連續數次不變＝到位或卡住；單段超時 ~15s。
3. 到位後被自己角色擋住（OCR 找不到目標層文字）→ 處理階梯（便宜→貴）：
   - a. `,` 轉 45°（`_rotate_verified`）：第三人稱角色永遠在畫面中央，鏡頭一轉面板偏離中央、脫離遮擋；近距斜視角下文字仍可讀，OCR 文字框照常給座標；
   - b. 再右鍵重導航一次（點面板偏左/右邊柱，讓角色站側邊；實測有時有效）；
   - c. 都不行 → reroll。
   - **不用第一人稱縮放**：Roblox 第一人稱鎖鼠標到準心，「點擊指定螢幕座標」前提崩壞，風險大於收益。

### C. OCR 文字框直接點擊
click-to-move 保證每次都走到面板正前方＝面板必然大而清晰，因此**不需要 homography/四角擬合/標準圖標注**——偵測與點擊合一：
1. 對面板 bbox 周邊區域跑 OCR（現有 RapidOCR **本來就回每行文字的框座標**，需在 `ocr` 模組外露 box 資訊——目前 `read_text_multi` 只回文字，實作時加介面）。
2. 模糊比對找到＝config 目標層名稱（如 `Mantle Layer`）的文字框，**對得上才點**（寧漏勿誤）；比對不到＝被擋住或不夠近 → 走遮擋階梯。
3. 左鍵點擊該文字框中心 → 幀差確認傳送 → 礦內簽名驗證 → `init_mining_sequence`。
4. 進礦成功發 Discord 通知附落點截圖（沿用 `notify` 事件表），人工遠端可查有無傳錯層。
5. 防呆：`Back to pre-reset location` 與各層按鈕名稱互為排除集——模糊比對必須**嚴格贏過**其他按鈕名稱的分數才點（比照 rare vs common 雙向最近鄰的既有做法）。

## 第 4 節：測試與診斷

- 純邏輯 TDD：`reentry.decide_step`（階段轉換）、面板候選排名/門檻判定、attempts 記帳、遮擋階梯決策、`decide_giveup`。
- 使用者提供的 4 張實機截圖（近距正面、遠距、橋對面、貼臉含遮擋）進 `tests/fixtures/surface/` 當偵測回歸集（比照 `test_ocr_fixtures.py` 慣例）；後續從 `logs/snapshots/manual/` 補樣本。
- log 進 `actions.log`＋`snapshots/reentry/` 子夾；成功/放棄都發 Discord。

## 風險邊界與明確不做的事

- 最壞結局＝attempts 用盡交 `NEEDS_HUMAN`＝今日現狀。
- 不做：盲走導航（W 短衝/跳躍/側移脫困）——click-to-move 取代；homography/四角擬合/標準圖標注——近距 OCR 文字框直接點取代；第一人稱縮放；旗幟/橋等單一世界地標模板；「Back to pre-reset location」按鈕（回舊深處座標，無意義）。
- 傳錯層＝效率問題非安全問題（仍會挖礦、可 reroll 回地表），v1 靠點前 OCR 驗證＋事後通知截圖把關，不做進礦後的層級自動判別。
