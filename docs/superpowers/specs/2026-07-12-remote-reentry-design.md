# Discord 遠端回礦（Remote Re-entry）設計

日期：2026-07-12
狀態：設計定案，待實作計畫
前置：`2026-07-08-mine-reentry-design.md`（全自動設計，保留不動）、`2026-07-11-discord-remote-aim-design.md`（網格指位/無前綴解析/分則發送零件）

## 目標與定位

礦坑重置後的回礦，目前 `RESET_WAIT` 等人工遠端桌面接管。本設計把它降級成「回幾則 Discord 訊息」：bot 傳地表、歸位角度、發八方位截圖，使用者指定點哪裡，bot 照點、驗證、回挖礦。

**雙重目的**：
1. **遠端人工模式（本版交付）**——每次重置由使用者遠端指位完成回礦。
2. **自動化材料收集（落盤設計為此服務）**——每次人工指位＝一筆 ground truth（「這張全幀裡目標按鈕在 (x,y)」）。**「原樣重放點擊座標」不可行**（重生點位置連續偏移＋初始 yaw 隨機、八方位相位每次差 0~45°）；正確路徑＝累積跨距離/角度/重生點的標注樣本 → 建面板多尺度偵測模板庫＋回歸集 → 「偵測面板 bbox → 版面固定比例換算目標按鈕 → 遠距直接點」的全自動（連 click-to-move＋OCR 都可省，2026-07-08 設計據此簡化）。離線評估腳本與自動重放**不在本版**，累積樣本後另案。

**可行性**：零件全現成（Discord 收發/無前綴解析/網格疊圖/驗證式旋轉/俯仰歸位/幀差驗證/防掛機）。最壞結局＝`跳過` 轉 NEEDS_HUMAN＝今日現狀。

## 已確認的事實與決策（2026-07-12 問答）

| 問題 | 決策/事實 |
|---|---|
| 功能定位 | 先遠端人工模式＋資料落盤；自動重放看過資料分佈再設計 |
| 指位精度 | **兩段式數位放大**：粗網格選格 → 該格裁圖放大＋細網格 → 細格換算絕對座標（±27px） |
| 開場訊息 | **八方位全掃一次發齊**（使用者回覆延遲以分鐘計，往返次數是最貴成本） |
| 按鈕辨識 | 使用者遠距**看不清按鈕文字**，靠「面板版面固定＋記第幾顆位置」點——遠端模式**不做按鈕 OCR 驗證**，把關改事後（傳送驗證＋落點截圖） |
| 遠距點選 | 大多數重生點可遠距直接點面板按鈕傳送；**少數世界/位置需先移動取位**（`走` 指令） |
| 目標層 | 黏性目標層：長期只指同一層、不想重複輸入；後續會換層收其他按鈕位置 |
| 防閒置 | 沿用既有 `Bot._antiafk_tick`（main.py，`antiafk_interval_s=900s` 按 Space），不另造 keepalive |

## 第 1 節：狀態機與 config

- config：`auto_reenter: bool` 改為 **`reentry_mode: "off" | "remote" | "auto"`**（預設 `off`＝今日行為＝RESET_WAIT 等人工；`auto`＝2026-07-08 全自動設計位，該設計不動）。
- `remote`：RESET_WAIT 既有 banner-消失＋沉澱偵測 → 進 `REENTRY`，走本設計流程。
- 決策純函式在**新模組 `reentry_remote.py`**（TDD）：指令解析、context/phase 小狀態機、格↔座標換算、疊圖參數。I/O 全在 `Bot._tick_reentry` 的 remote 分支。
- 與 remote-aim 的關係：網格疊圖/格中心換算/分則發送零件從 `remote_aim.py` 抽成共用（既有 remote-aim 測試全數不變）；**無前綴訊息分派給「當前存活的 context」**（harvest giveup → aim context；回礦等待 → reentry context；兩者不會同時存活）。
- Q / Ctrl+Q / F12 全程有效；每階段查 `_mine_resetting`（等待中又重置 → 作廢 context、回 RESET_WAIT）。

## 第 2 節：開場流程

```
按「回到地表」(固定UI座標盲點) → 幀差等傳送完成
→ 俯仰歸位（拖到夾限→回拉；pitch_eaten_* 獨立門檻，已校準）
→ `,`×8 八方位（_rotate_verified），各拍全幀、記各方位 net_rotations
→ 疊 6×4 粗網格（欄 A–F、列 1–4，半透明，重用 remote-aim 疊圖）
→ Discord 分則發送（每則 ≤4 張、caption 標方位）；首則附：
   episode 編號（`回礦 #NNN`）、當前目標層、指令說明
→ 進入等待回覆；等待期間每輪 tick 呼叫 _antiafk_tick("回礦等待指令")
```

## 第 3 節：指令詞彙（reentry context 存活時，無前綴訊息即指令）

| 回覆 | 動作 |
|---|---|
| `3 C2` | 轉到方位 3（`plan_return_rotations` 最短路徑、驗證式）→ 裁 C2 格（320×270）數位放大＋疊 **6×6** 細網格（欄 A–F、列 1–6）→ 回傳單張，進「等細格」 |
| `B3`（等細格時） | 換算絕對螢幕座標 → 漂移守門 → 左鍵點擊 → 進驗證（見第 4 節）。細格一格 ≈53×45px、誤差 ±27px |
| `B3 Core` | 同上，**本次點擊**的層標籤覆寫為 Core（黏性值不變） |
| `層 Core` | 改黏性目標層（session 內沿用），回覆確認。跨重啟預設值在 config `reentry_target_layer` |
| `走 C2` | 右鍵 click-to-move 到**當前面向**幀的 C2 格中心 → 等到位（幀穩定，~15s 超時）→ 重拍當前面向＋粗網格回傳單張。走位後其餘方位快照視為過期 |
| `掃` | 重新八方位掃描發送（走位後想換方向用） |
| `重骰` | 再按「回到地表」換重生點，整輪重來（episode 同號、attempt+1 記帳；human-driven 不設上限） |
| `好`（等確認時） | 驗證不確定分支的人工放行 → init 序列回 MINING |
| `作廢` | 上一筆點擊在 ledger 標 `invalid`（點歪/層標錯，防污染資料集） |
| `跳過` | 放棄 → NEEDS_HUMAN 等遠端桌面接管 |
| 其他/越界/非法時機 | 回格式提示，不動作；執行中收到新訊息回「執行中稍候」；已作廢 episode 的遲到回覆回「該輪已結束」 |

- `!` 前綴訊息照舊走舊命令分派，不進本解析。
- 一次只執行一個指令，不排隊。

### `走` 的前置：Movement Mode 懶啟動

右鍵 click-to-move 依賴移動模式設定，選單鏈現為備而不用。**session 第一次收到 `走` 才跑鏈**（`menu_budget_s=90s` 預算）；失敗回報「走位不可用，請重骰或跳過」。不在開場跑——大多數 episode 用不到。

## 第 4 節：點擊防漂移、驗證與回報

- **點擊前漂移守門（H026 家族）**：細格回覆可能已隔數分鐘（D5 buff 到期 FOV 縮放、antiafk 跳躍、場景光影）。點擊前重截當下幀、與放大圖同區域幀差——差異大 → **不點**，重發更新後的放大圖請使用者重指。
- **點擊後三態**：
  1. **成功**：幀差大變化＋礦內亮度簽名（`calibrate_surface --brightness` 產物）通過 → `init_mining_sequence` 回 MINING；回報訊息附兩張圖：**①點擊前幀＋紅圈標實際點擊座標**（核對沒點歪）、**②落點截圖**（核對傳對層）；context 作廢。
  2. **不確定**（幀差有變但簽名未校準/不過）：回報同兩張圖，等 `好`（放行開挖）或 `重骰`／`作廢`。
  3. **無反應**（幀差近零＝點到空地）：不進驗證，回報「畫面無變化」＋重發當前放大圖，留在等指令。
- 點錯層＝效率問題：使用者從落點截圖看出 → `重骰`（必要時 `作廢` 修資料）。

## 第 5 節：資料落盤（自動化材料＋證據）

每 episode 一行 JSONL（`logs/reentry_remote/ledger.jsonl`），欄位：

- episode 編號、時間、世界（`game_data` 當前鎖定，未鎖＝null）、attempt 數
- 俯仰歸位量、八方位快照路徑＋各方位 net_rotations
- 指令流水：每則原文＋解析結果＋執行時姿態＋時間戳（`走` 的使用自然標出「遠距點不到」的場景）
- zoom 鏈：粗格、裁圖區域、細格、換算後絕對點擊座標
- **層標籤**（黏性值或單次覆寫；純使用者宣告，bot 無法驗證——正確性靠落點截圖核對＋`作廢` 修正）
- 驗證結果（成功/人工放行/無反應/重骰/跳過）、`invalid` 旗標、總耗時

快照（非同步 snapshot worker，`snapshots/reentry/`）：

- 八方位原始掃描幀（偵測未來要在這種遠景圖上工作）
- **點擊瞬間全幀**＋**以點擊點為中心的兩層裁圖**（按鈕級/面板級，直接當模板候選與回歸樣本）
- 落點截圖

## 第 6 節：HUD 與雜項

- HUD 顯示「REENTRY 等待指令 #NNN（已等 N 分）」＋最後一則指令（文字走 `_bmp_safe`，不放 astral emoji）。
- log 進 `actions.log`（動作）＋`discord.log`（收發），比照既有分檔。
- 所有輸入前 `_focus_roblox`。

## 第 7 節：測試與完成標準

- `reentry_remote.py` 純函式 TDD：
  - 解析全案例：全詞彙、全形空白、大小寫、越界格子、非法時機（未等細格時回細格、context 作廢後回覆）、層名覆寫
  - 粗格→裁圖區域、細格→絕對座標換算（含 rounding、邊緣格）
  - context 生命週期：建立/作廢時機、episode 編號、`作廢` 對最後一筆的定位
  - phase 決策：開場→等指令→等細格→等確認→收尾各轉換
- 共用零件抽出後 remote-aim 既有測試全綠不改。
- ledger 寫入格式的單元測試（欄位齊全、invalid 標記）。
- 完成標準：`python -m pytest -q` 全綠；實機端到端＝真實重置一次，手機完成整輪指位回礦（含一次 `重骰`、一次兩段放大點擊、驗證回 MINING）。

## 風險與對策

| 風險 | 對策 |
|---|---|
| 點歪/傳錯層 | 紅圈標記圖＋落點截圖事後核對；`重骰` 重來；`作廢` 修資料；點前不加確認往返（延遲成本高於點歪代價） |
| 座標漂移（buff 到期/antiafk 跳躍） | 點擊前幀差守門，差異大不點、重發放大圖 |
| 等待中被踢 | 既有 `_antiafk_tick`（900s Space），等待分支照呼叫 |
| 等待中礦又重置 | 每階段查 `_mine_resetting` → 作廢 context 回 RESET_WAIT |
| 舊回覆打到新局勢 | episode 編號＋context 作廢；「該輪已結束」不動作 |
| `走` 依賴移動模式未設 | 懶啟動選單鏈＋失敗明確回報，不影響不用 `走` 的主流程 |
| 錯誤標注污染自動化資料 | `作廢` 指令＋層標籤明示「使用者宣告、未驗證」語意 |

## 明確不做（本版）

- 自動重放/場景比對查表（樣本累積後另案，先做離線偵測評估）
- 點擊前確認往返、落點層數自動判別、按鈕文字 OCR（遠距看不清，人工也靠版面記位）
- 離線評估腳本

## 2026-07-13 addendum：H043 虛空墜落實錄修正

首三次實機 run 全滅的根因＝**設計假設「重置後按回到地表即可傳送」不成立**：RESET_WAIT 等
banner 消失才進 REENTRY，重置瞬間人還在礦內 → 礦體消失自由落體墜入虛空（Depth 33M+、畫面
全黑），虛空下墜狀態「Go to surface」幾乎不回應（瞬間點/hold/懸停全滅、僅偶發成功）；
地表狀態同一點擊 100% 有效。完整敘事見 docs/incidents.md H043。

設計修正：
1. **RESET_WAIT 進場即撤離**（remote 模式限定）：banner 出現時礦體還在、點擊可靠，先按
   回到地表離開；REENTRY 開場再按一次＝換重生點（原 reroll 語意不變）。
2. 撤離/開場點擊共用 `_click_surface_verified`：幀差驗證＋`reentry_click_retries=3` 重試，
   重試前游標移中央再移回（多一次真實滑鼠移動事件）。
3. `reentry_teleport_diff` 25→12：虛空→夜間地表傳送後穩定幀差僅 ~19（兩側夾：噪音 ≤4.4、
   換重生點最低 26.8）。
4. 開場失敗警告附當下截圖（全黑＝虛空一眼可辨）；所有 RR 發送走 `_rr_notify` 記送達結果。
5. **互動 embed 化**（使用者需求）：episode 卡片（attempt/目標層/已等分鐘/階段色）原地
   PATCH 更新、收尾刪卡；🎲重骰/⏭️跳過/📷重掃反應鈕與文字指令同走 `_pending_reentry`，
   主迴圈消費路徑零改動。純函式 `build_reentry_embed`/`reaction_to_reentry_reply`（有測試）。
