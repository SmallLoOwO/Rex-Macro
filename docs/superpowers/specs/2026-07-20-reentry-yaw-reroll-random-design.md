## 背景與症狀

2026-07-20 使用者反映：回礦中用 Discord 下偶數方位（`2`/`4`/`6`/`8`＝對角 45°／135°／225°／315°）指位、成功下礦後，挖礦時角色仍朝對角、W 往斜向走。`b9f7783`「回礦收尾補 yaw 回正」原應避免斜向帶進挖礦，實機無效。

## 探查結果（根因）

### 證據 1：07-08 設計 spec 明文記載「reroll 亂 yaw」

`docs/superpowers/specs/2026-07-08-mine-reentry-design.md:18`：

> | 防範機制 | **隨機旋轉只亂 yaw**；俯仰是挖礦自己抬頭弄歪的殘留 | 俯仰用「拖到底夾限→回拉固定量」歸位；yaw 用 `,`/`.` 八方位掃描 |

回礦的傳送（reroll＝「回到地表」換重生點）會把角色 yaw 隨機化——這是 07-08 設計時就知的遊戲機制。八方位掃描的整個設計就是為了「在隨機 yaw 下照樣拍到傳送板」，**不嘗試把 yaw 轉回原值**。

### 證據 2：b9f7783 的假設 vs 實機行為

`b9f7783` commit message 主張：「teleport 保留 yaw（實機確認），反向送鍵轉回即回到開場 sweep 起始面向」。`_rr_success` 加了：

```python
self._pitch_home_mining(f"[RR#{ctx.episode_id}] 回礦收尾")
harvester.restore_view(ctx.cur_dir, rotate=self._rotate_verified)
self._rr_finalize(outcome)
```

實機 `harvest.log`（07-20 RR#10／RR#11，皆 attempt 4＝reroll 過）證實 `restore_view` **有執行、旋轉次數正確**：

- **RR#10**：使用者下方位 4（dir_idx=3，對角），收尾 19:44:53~55 左轉 `,` 3 次（對應 `cur_dir=3` 的 `restore_actions`）
- **RR#11**：使用者下方位 6（dir_idx=5，對角），收尾 20:28:15~16 右轉 `.` 3 次（對應 `normalize(5)=-3`）

數學與執行都正確。但使用者仍觀察到對角——因為**轉回的 `cur_dir=0` 不是絕對正面，而是 reroll 的隨機 yaw**。

### 證據 3： 礦層面向＝重生點最後面向（使用者實機確認）

使用者確認：點擊傳送板進 礦層後，角色面向＝重生點最後面向（teleport 保留 yaw）。所以：

> ** 礦層面向＝reroll 隨機 yaw＋使用者選的偏移＝完全隨機**

### 根因一句話

**reroll 隨機化 yaw 是遊戲機制，腳本沒有絕對 yaw 感測器；b9f7783 的 `cur_dir` 記帳是「相對 reroll 後隨機面向」的偏移，轉回 `cur_dir=0` 只是回到那個隨機基底，約 50% 落在對角。** 轉與不轉結果都是隨機：

| 收尾做法 | 礦層最終面向 | 直角（0/90/180/270）機率 |
|---|---|---|
| b9f7783 `restore_view(cur_dir)` | reroll 基底 yaw（去掉使用者偏移） | ~50% |
| 不轉（b9f7783 前） | reroll 基底 yaw ＋ 使用者偏移 | ~50% |

`b9f7783` 唯一真正有效的情境是 **attempt 1（沒 reroll、第一次進場的 teleport 確實保留 yaw）**——此時 sweep 起始面向＝挖礦原視角（直角），`restore_view` 才轉得回正面。**一旦 reroll，地基（＝挖礦原視角這個已知直角）消失，記帳失去意義。**

### 排除的假設

調查過程一度懷疑下列，逐一以 log／模擬否證：

- ✗ `restore_view` 沒執行 → harvest.log debug 區有旋轉紀錄（19:44:53~55、20:28:15~16）
- ✗ 旋轉次數算錯 → Python 模擬 −8~+15 全範圍 `cur_dir`，`normalize_rotations`／`restore_actions` 全部正確
- ✗ `init_mining_sequence` 的 `rotate(.,)` 破壞 yaw → 成對淨 0，log 顯示兩鍵都生效
- △ reroll 偏移累積 → 部分相關（`_rr_ensure_ctx` reroll 時 `cur_dir=0` 但不轉回角色實際面向，line 4441），但**不是主因**——即使完美對齊，reroll 後基底 yaw 仍隨機

## 修復計畫：視覺校正 yaw 到直角

### 目標

 礦層挖礦開始前（回礦收尾或 MINING 入口），用視覺判斷當前 yaw 是直角（90° 倍數）還對角（45° 奇數倍），若對角則補轉一次 `,`/`.` 到直角。**不依賴任何記帳**，reroll 多隨機都能對齊。

### 演算法框架（候選訊號，需視覺評估擇一或融合）

偵測 礦層畫面中具「絕對朝向」的參考。候選：

1. **地板格線／紋理主方向**： 礦層地板若是方格，邊緣方向直方圖（edge orientation histogram）主峰在 0°／90°＝直角面向；在 45°／135°＝對角。
2. ** 礦脈／通道走向**： 礦脈通常沿固定軸向延伸，偵測其主方向。
3. **HUD／小地圖 compass**：若遊戲 UI 有方向指示，直接 OCR／偵測（最可靠，需先確認 UI 存在）。

實作雛形：抽 ROI（避開角色模型／中央 UI）→ Canny 邊緣 → 方向直方圖 → 主峰落在哪個 45° 槽決定當前 yaw 類別。信心不足（直方圖扁平、地形太亂）→ 不轉，記 warning。
